# 명지전문대 현재 수신 원자료 ZIP

명지전문대 선택 후 성적 파일에서 일반 ZIP 또는 기존 통합 Excel을 선택한다.
일반 ZIP은 다음 파일을 포함해야 한다. 전체를 감싸는 폴더 하나가 있어도 된다.

```text
execution.csv
file-index.csv
parts/
  current-part-0001-applicants.csv
  current-part-0001-raw_student_records.csv
  current-part-0001-raw_student_subjects.csv
  ... 나머지 원자료 및 모든 part
```

원본 AES 암호화 ZIP은 사용자가 먼저 해제하고, 해제한 폴더를 일반 ZIP으로 다시 압축한다.
최대 업로드 크기는 200MB, ZIP 내부 전체 해제 크기는 1GB다. 과목을 Excel로 병합하지 않는다.

1. 대학과 검증 기준연도를 선택하고 ZIP을 한 번 업로드한다.
2. 최근 가져오기에서 저장 완료를 확인한다.
3. 성적 검증을 실행한다.
4. 결과 다운로드에서 계산 근거와 원자료 연결 및 보조값을 확인한다.

ZIP의 대학·학년도·원자료 기준, part 구성, 파일별 행 수와 지원자별 연결을 검사한다.
모든 part를 하나의 교체 트랜잭션으로 저장하며 실패 시 기존 저장본을 유지한다.
실제 운영 DB에서의 검증과 업로드는 사용자가 수행한다. 개발 테스트는 합성 자료만 사용한다.

학생부 기본정보가 없는 지원자도 명세에서 제거하지 않는다. 복수 학생부는 과목을 원자료로
보존하지만 임의로 선택하거나 합산하지 않고 미산출 처리한다. 검정고시에서는 유효 원본이
정확히 하나일 때만 계산하며 필수과목 누락·중복은 미산출 처리한다. 출결·수동설정·평가점수는
이번 내신점수에 적용하지 않는다. 실기·면접 합산과 최종 순위 판정은 수행하지 않는다.

현재 명시적으로 인식하는 `academicRecordType` 값은 원자료의 `STUDENT_RECORD`(학생부), `GED`,
내부 호환 코드 `DOMESTIC_HIGH_SCHOOL`, `FOREIGN_HIGH_SCHOOL`이다. `STUDENT_RECORD`는
학생부 계산 경로인 `DOMESTIC_HIGH_SCHOOL`로 연결한다. 값이 비어 있으면 학생부 또는 검정고시 한 종류만 있는 경우에만
분류한다. 다른 코드는 의미가 확인될 때까지 `ACADEMIC_TYPE_UNRESOLVED`로 남기며 추측하지 않는다.
학력 코드 미인식과 학생부·검정고시 원본 미연결·복수 연결은 각각 다른 경고와 건수로 표시한다.
과거 업로드에서 이미 코드 미인식으로 저장한 연결 정보는 재시작만으로 바뀌지 않으므로
수정 후 원본 ZIP을 다시 업로드한 다음 성적검증을 실행한다.
외국고 및 게시 규칙이 없는 전형은 기존 계산 경로에 따라 미산출될 수 있다.

## 현재 코드 목록에 따른 연결

`일반[실기위주]`, `일반[면접위주]`, `특별[대학자체기준(어학우수자)]`는 각각 기존 게시 규칙의
일반 실기·일반 면접·대학자체기준 전형으로 연결한다. 기존 2026 자료의 합쳐진
`일반[실기·면접위주]`도 계속 지원한다. 농어촌·기회균형의 실기학과 그룹은 실용음악·연극영상이며,
문예창작·산업디자인·사회체육을 일반 실기전형이라는 이유로 같은 배점 그룹에 넣지 않는다.
이 연결은 내신 배점을 선택하기 위한 것이며 실기·면접 점수를 계산하거나 합산하지 않는다.

전형 코드 `0301`(전문대학이상)은 `PREVIOUS_COLLEGE_RECORD_REQUIRED`로 구분한다.
해당 대상은 고교 학생부 미연결이나 게시 규칙 부재 대신 전적대학 성적 입력 필요 사유를 표시하고,
고교 학생부·검정고시 점수로 대체 산출하지 않는다. 전적대학 성적 계산 기능을 추가한 것은 아니다.

`graduationStatus`가 null·빈칸이면 졸업일의 연도, 학생부 `graduateYear` 순서로 사용한다.
기준 학년도보다 이전이면 졸업, 같은 해 또는 이후이면 졸업예정으로 저장한다. 연도도 없으면
공통 Student 정책과 같이 졸업예정을 기본값으로 사용하며, 이 기본값이 졸업 상태 확인을 뜻하지는 않는다.
명시적인 졸업·졸업예정 값은 우선한다. 고교 유형 입력이 비어 있으면 기존 GENERAL 기본값을
유지하므로, 그 값만으로 실제 학교 유형이 확인됐다고 해석하지 않는다.

`subjectSeparationCode`의 `02`/`2`는 기존 2026 판독기와 동일하게 진로선택으로 처리한다.
`01`·`03`·null에는 진로선택 표시를 하지 않으며 세부 명칭을 새로 추정하지 않는다.
`subjectReqCode`의 `0/1/OPT/REQ`는 숫자·문자 사이의 대응 정의가 확인되지 않았으므로 새 매핑을
만들지 않는다. 검정고시 필수 6과목 확인과 6·4·2 단위 배정은 기존 과목명 기준을 유지한다.
`rankingGradeCode`·`achievementCode`도 원래 등급·성취도의 대체값으로 사용하지 않는다.

위 메타데이터·졸업상태 변경을 기존 저장본에 적용하려면 수정한 서버로 ZIP을 다시 업로드한다.
개발·회귀 테스트에는 합성 원자료만 사용하며 실제 지원자 파일이나 DB를 자동 재조회하지 않는다.

새 형식은 `MJC_CURRENT_SOURCE_ZIP_V1`이다. 실행 전에 백엔드를 재시작해 Flyway V59를
적용해야 한다. 원자료 ID는 가져오기 과목 저장본과 지원자 메타데이터에 보존한다.
오류 로그에는 ZIP의 원자료 값과 파서·SQL 예외 전문을 출력하지 않는다.

ZIP 업로드 기능은 기존 학생부 계산기를 연결한다. 이 변경 자체가 대학별 모든 산식과
동점자 처리 규정에 대한 최종 검수를 의미하지 않는다. 학생부 학기별 중간값은 기존 출력,
검정고시 과목별 환산 및 동점자 보조값은 원자료 연결 및 보조값 시트에 기록한다.
과목 비교 출력이 Excel 행 한도에 도달하면 지원자 단위로 다음 시트를 만든다.

## 가져오기 실패 진단

HTTP 202는 저장 완료가 아니라 백그라운드 작업 접수다. 최근 가져오기에서 완료 여부를 확인한다.
실패하면 `[MJC_IMPORT_FAILED]`로 시작하는 오류에 처리 단계, 파일 종류·part·행,
인식 가능한 컬럼 검사 또는 SQLState·DB 오류 번호를 표시한다. CSV 값, SQL 전문,
수험번호 및 원본 예외 메시지는 출력하지 않는다. 해당 오류 문구만으로 실패 위치를 공유할 수 있다.
과거 버전의 포괄적인 오류로 실패한 작업은 진단을 소급 복구할 수 없으므로 수정된 서버에서
한 번 다시 업로드해야 한다. 저장이 실패한 상태에서 성적검증을 먼저 실행하면 최신 저장본을 검증할 수 없다.

## 숫자로 해석되지 않는 석차등급 표기

`rankingGrade`가 1~9의 정수 등급으로 해석되지 않아도 그 과목 행을 버리거나 전체 저장을
실패시키지 않는다. 원문은 `source_grade_text`에 보존하고 숫자 등급만 비운다. 가져오기 이력에는
해석을 보류한 표기의 건수를 표시한다. P·이수·우수·보통·미흡, 가운데점 `·`, 마침표 `.`,
A~E(대소문자 무관)는 인식 가능한 비수치 표기로 처리한다. 이 표기 자체를 숫자 등급으로
변환하거나 `achievement` 컬럼에 덮어쓰지 않는다.

명지 2026·2027 학생부 계산 규칙은 원점수·평균·양수 표준편차로 Z값 환산이 가능하면 기존
Z값 환산을 적용하고, 환산할 수 없는 과목은 해당 과목만 제외한다. A~E 또는 점 표기 때문에
지원자 전체를 중단하지 않는다. 반영된 과목의 계산 내역에는 환산등급을, 제외 과목에는 제외 사유를
남기며, 원본 표기는 어느 경우에도 상세와 저장 결과에 보존한다. 숫자 석차등급·석차백분율의
우선순위, 반올림, 우수학기 선택 및 학년별 반영 비율은 바꾸지 않는다.

의미를 확인하지 못한 표기가 양수 이수단위의 반영 학년·학기에 있으면 해당 지원자는
`MJC_SOURCE_GRADE_REVIEW_REQUIRED`로 미산출한다. 숫자 등급이 없는 것을 곧바로 성적 없음으로
간주해 9등급 보정하거나, 임의의 다른 환산으로 점수를 확정하지 않는다. 0단위 또는 반영 범위 밖의
과목은 원문을 보존하면서도 정상 과목의 계산을 막지 않는다.

위 인식 표기의 판정 변경은 이미 저장된 `source_grade_text`에도 적용되므로, 이전 가져오기가
완료된 자료는 재업로드 없이 수정된 백엔드에서 성적검증을 다시 실행하면 된다. 과거 가져오기 이력의
미해석 건수와 기존 검증 회차는 소급 변경하지 않는다. 실제 지원자 자료를 다시 읽어 원인이나
해결 인원을 확인한 것은 아니므로, 모든 기존 미산출 지원자가 해결된다고 단정하지 않는다.

2026·2027 합성 회귀 테스트는 같은 A~E 및 점 표기에서도 원점수에 따라 서로 다른 Z값 등급이
계산되는지, 입력 누락·0 또는 음수 표준편차이면 해당 과목만 제외되는지, 원문·제외 사유·반영 단위와
Excel 출력이 보존되는지 확인한다. 미확인 문자열의 중단 및 비반영 범위 예외 테스트도 유지한다.
2026-10-28 전체 Java 소스 직접 컴파일 및 JUnit 실행: 499개 성공, 1개 건너뜀, 실패 0개.
Gradle wrapper는 환경의 `Unable to establish loopback connection` 오류로 실행되지 않았으며,
실제 지원자 자료 또는 운영 DB로 결과를 재산출한 검증은 포함하지 않는다.

## 전체 지원자 Excel 출력

명지전문대 `학생별 검증 결과`는 성공·실패를 합쳐 지원정보 순서대로 한 지원자당 한 행을
출력한다. 실패한 지원자도 지원정보 행·수험번호·전형명·모집단위명을 표시하고, 중간 산출값은
비워 둔 채 마지막 `교과 반영점수` 칸에 숫자 `0`만 표시한다. 이는 Excel 출력용 표시이며
미산출을 산출 성공으로 바꾸거나 DB에 계산 점수 0을 저장하는 변경이 아니다.

`검증 요약`에는 `미검증 학생 목록`으로 실패 코드·사유·코드별 인원·합계를 표시하고, 아래의
필터 가능한 `성적 검증 실패 상세`에서 해당 지원자를 확인한다. 실제 계산이 완료된 0점이
있으면 `산출 완료 0점 학생`에 별도로 표시하고 미검증 인원에는 더하지 않는다. 실패자 전용
결과 시트를 추가하지 않으며 기존 과목 비교와 원자료 보조값 시트는 유지한다.

저장 결과 내보내기도 같은 업로드의 전체 지원정보를 조회하여 성공·실패 행을 합친다.
원자료가 교체되어 전체 지원정보를 복원하지 못하면 기존 경고와 `확인 불가` 집계를 유지한다.
형식 변경만 적용할 때는 데이터 재업로드나 성적 재계산 없이 수정된 백엔드에서 Excel을
다시 생성하면 된다. 이미 생성된 내보내기 파일은 바뀌지 않으므로 서버 재시작 후 새로 생성한다.

합성 12개 part의 성공·실패 혼합, 전원 미산출, 실제 산출 0점, 저장 회차의 원본 교체와
실패 사유 복원을 회귀 검증한다. 운영 원자료·DB를 조회하거나 기존 결과를 수정하지 않는다.
