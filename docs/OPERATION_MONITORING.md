# 데이터 현황과 작업 확인

`/api/operations/data-status`는 대학·연도별 학생 존재와 최근 업로드 처리, 업로드와 연결된
일괄 검증 결과 유무 및 최근 일시를 조회한다. 대용량 과목 테이블의 전체 건수 집계는 수행하지
않는다. 수동 개별 검증은 일괄 결과에 포함하지 않으며, 검증 미산출만 있고 저장된 점수 결과가
없는 회차는 검증 결과 없음으로 나타난다. 최신 업로드 상태가 실패하더라도 이전 학생 데이터가
남아 있으면 존재로 나타날 수 있다. 과거 원자료 삭제 등으로 이력과 현재 데이터가 다를 수 있다.

`/api/operations/active-jobs`는 현재 프로세스에 등록된 명지·삼육 비동기 원자료 저장, 일괄 검증,
엑셀 생성 작업을 보여준다. 업로드의 브라우저→서버 전송은 서버에서 작업을 접수하기 전이라
표시하지 못한다. 일반 동기 업로드와 개별 학생 검증도 이 목록에 포함하지 않는다. 서버가 재시작되면
메모리 작업 목록은 초기화된다. 서버 재시작 중 끊긴 작업은 계속 실행 중으로 표시하지 않는다.
파일 저장·내보내기는 전체 비율이 없어 미정으로 표시한다. 성적 검증은 확인 가능한 저장 처리 건수를
전체 지원자 수와 함께 보여주며, 처리 중 누락·미산출 건수는 마지막에 확정되므로 완료율 보장은 아니다.
처리된 저장 건수는 트랜잭션이 성공적으로 확정되기 전에는 임시 값이다.

`/api/operations/rule-change-history`는 `src/main/resources/rule-change-history.json`의 선별 기록을
읽는다. Git 커밋에 실제 반영된 변경과 관련 대화에서 확인한 이유를 선별해 옮겼고, 확인할 수 없는 변경 이유는
미기록으로 남겼다. 과거 전체 변경이나 실제 배포 시각의 완전한 감사 기록은 아니다. 이후 산출 로직을
바꿀 때는 해당 JSON에 실제 학교, 내용, 시각, 확인된 이유를 같은 변경으로 추가한다. 커밋 식별자가
확정되지 않았을 때는 `null`로 두며 추측하지 않는다. 코드상 기록의 수동 관리이며 자동 이력 생성은 아니다.
